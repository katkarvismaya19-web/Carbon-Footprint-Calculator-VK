\# Week 1 – Problem Definition and Project Scope



\## Project Title

Carbon Footprint Calculator – DevOps Automation and CI/CD Deployment



\## Objective



The objective of Week 1 was to understand the Carbon Footprint Calculator application, identify the problem to be addressed, define the project scope, and establish the objectives of the DevOps project.



\## Problem Statement



The Carbon Footprint Calculator is a Java-based web application that allows users to record activities and calculate their associated carbon emissions.



The main DevOps challenge was to establish an automated software development and deployment process so that the application could be built, tested, deployed, and verified consistently.



\## Project Objectives



The main objectives identified during Week 1 were:



\- Understand the existing Carbon Footprint Calculator application.

\- Define the project scope and expected outcomes.

\- Automate the application build process.

\- Automate unit testing and code quality verification.

\- Implement Continuous Integration and Continuous Deployment.

\- Deploy the application on Apache Tomcat.

\- Perform automated end-to-end testing using Selenium.

\- Containerize the application using Docker.

\- Use Ansible for configuration verification.

\- Implement deployment health checks.

\- Provide deployment backup and rollback capability.

\- Establish a complete and repeatable DevOps pipeline.



\## Project Scope



The project covers the complete software delivery lifecycle:



1\. Source code management using Git and GitHub.

2\. Automated builds using Apache Ant.

3\. Unit testing using JUnit.

4\. Code coverage using JaCoCo.

5\. WAR package creation.

6\. Automated deployment to Apache Tomcat.

7\. Browser-based end-to-end testing using Selenium.

8\. Docker containerization.

9\. Docker-based deployment and health verification.

10\. Ansible-based environment configuration verification.

11\. Idempotency validation.

12\. Deployment backup and rollback.

13\. Final application health verification.



\## Expected Outcome



The expected outcome was a complete automated CI/CD pipeline capable of taking application source code from GitHub, building and testing it, generating the WAR package, deploying it, performing automated verification, containerizing the application, validating the environment, and performing final release checks.
