\# Week 2 – Agile Planning and DevOps Workflow



\## Objective



The objective of Week 2 was to plan the Carbon Footprint Calculator project using Agile principles and define the DevOps workflow that would be followed throughout the project.



\## Agile Planning



A product backlog was prepared to identify and prioritize the major application and DevOps tasks.



The backlog included:



\- Carbon Footprint Calculator UI development

\- Transportation input

\- Electricity consumption input

\- Carbon emission calculation

\- Carbon footprint result display

\- Carbon reduction suggestions

\- Input validation

\- Git and GitHub setup

\- Jenkins configuration

\- CI pipeline creation

\- Automated testing

\- Automated deployment

\- End-to-end testing

\- Project documentation

\- Final presentation and demonstration



\## User Stories



User stories were defined from both the application user's and developer's perspective.



Examples include:



\- As a user, I want to enter transportation details so that transportation-related emissions can be calculated.

\- As a user, I want to enter electricity consumption so that energy-related emissions can be calculated.

\- As a user, I want the system to calculate my total carbon footprint automatically.

\- As a developer, I want the source code to be maintained in GitHub so that changes can be tracked.

\- As a developer, I want Jenkins to automatically build and test the application.

\- As a developer, I want successful builds to be deployed automatically.



\## Acceptance Criteria



Acceptance criteria were defined to determine when individual requirements would be considered complete.



The criteria covered:



\- Valid and invalid input handling

\- Correct carbon emission calculations

\- Clear display of results

\- GitHub source-code management

\- Successful automated builds

\- Automated test execution

\- Automated deployment

\- Jenkins build and deployment status



\## DevOps Workflow



The planned DevOps workflow was:



Developer

↓

Code Development

↓

Git

↓

GitHub

↓

Jenkins

↓

Source Code Checkout

↓

Build

↓

Automated Testing

↓

Deployment

↓

Application Verification



The workflow was designed to reduce manual build and deployment activities and provide a repeatable software delivery process.



\## Definition of Done



A task was considered complete when:



\- Required functionality was implemented.

\- Acceptance criteria were satisfied.

\- Testing was completed.

\- Identified issues were addressed.

\- Changes were committed to GitHub.

\- The application continued to work after integration.

\- Relevant documentation was updated.



For DevOps activities, successful build, testing, deployment, and application verification were also included in the Definition of Done.



\## Week 2 Outcome



The project backlog, user stories, acceptance criteria, DevOps workflow, and Definition of Done were established.



This provided a structured Agile plan for implementing and automating the Carbon Footprint Calculator throughout the remaining project weeks.
